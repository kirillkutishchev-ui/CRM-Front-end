# RabbitMQ: локальная реализация и проверка

Дата: 12 ноября 2026 года. Ветка: `feature/rabbitmq-outbox`.

Изменения реализованы локально. Публикация в GitHub и развёртывание на production не выполнялись.

## Выполнено

- RabbitMQ, durable topic `crm.events`, очереди `analytics_tasks`, `file_processing`, `websocket_notifications`, маршруты из ТЗ, `crm.dlx` и отдельные DLQ.
- Постоянное AMQP-соединение в процессе publisher/worker, Composer-зависимость php-amqplib, параметры подключения в приватном `.env`.
- Транзакционный outbox в MariaDB, persistent-сообщения, publisher confirms, ручные ACK. MariaDB хранит данные, а обработчиками являются отдельные PHP-воркеры.
- Фоновая аналитика и подтверждение закрытия смены. Финансовые записи, статус Closed и результат задачи фиксируются в одной транзакции.
- Контекст инициатора и повторная проверка актуальных ACL в обработчике и при выдаче результата. Регистрация, роли и проверка входа остаются синхронными.
- Счётчик попыток фиксируется до выполнения: SIGKILL/OOM не обнуляет его. Конкурирующие доставки проверяются по номеру попытки. Повтор завершённой задачи не дублирует финансовые записи.
- Ограниченные повторы, статус Failed и DLQ. Исправленный ручной повтор создаёт новую задачу с retryOfId; исходный payload сохраняется.
- Heartbeat и жёсткий лимит времени MQ_TASK_TIMEOUT_SECONDS; перезапуск средствами Docker, без Supervisor.
- Сохранение проверки смены блокируется ответом 409, пока подтверждение закрытия находится в очереди.
- Зарегистрирован WebSocket topic studioMqTaskCompleted, адресная отправка инициатору и подписка интерфейса. Ошибка транспорта вызывает повтор. HTTP-проверка результата сохраняется при потере событий или соединения.
- Проверка реальных изображений и lossless-оптимизация PNG. Меньшая копия используется для превью через read-only screenshotOptimizations.
- Необязательный HTTPS-контейнер панели RabbitMQ: compose.mq-management.yaml, TLS-сертификат и IP/CIDR из переменных окружения; остальные IP получают 403.
- Синхронизированы относящиеся к патчу файлы установочного пакета extensions/studio-management/files.

## Проверено

- RabbitMQ integration: 67 проверок с отдельными фикстурами, включая реальные SIGKILL, DLQ, повтор, ACL, материалы и однократное финансовое закрытие.
- Workflow integration: 92 проверки, фикстуры откатились.
- Клиентские проверки: RabbitMQ 24, Workflow 46, Shift review 32, Analytics 91.
- Архитектурные проверки: 96; PHP-синтаксис и git diff --check прошли.
- Реальный авторизованный WAMP/WebSocket-клиент получил событие, затем результат был проверен HTTP-запросом с ACL.
- При остановке брокера HTTP-запрос сохранился в outbox; после запуска брокера задача выполнилась и потребители переподключились.
- Проверка здоровья отвергает устаревший heartbeat; превышение времени завершает процесс с кодом 124.
- HTTPS-панель: разрешённый IP — 200, запрещённый — 403.
- После интеграционных тестов все три очереди и три DLQ пусты, нет неподтверждённых сообщений.

## Локальные адреса

- CRM: http://localhost:8098/
- WebSocket: ws://localhost:8099
- RabbitMQ Management: http://127.0.0.1:15673/
- Дополнительная HTTPS-панель: https://localhost:15674/ — временный локальный сертификат, требуется подтверждение доверия браузером.
- Пароли находятся в игнорируемом `.env.mq-local`.

Всегда указывайте `--env-file .env.mq-local -p crm-rabbitmq-local`. Этот проект использует отдельные volumes. Для HTTPS-панели дополнительно указывайте `-f compose.yaml -f compose.mq-management.yaml`.

## Границы и перенос на production

Оригиналы изображений сохраняются. JPEG/WebP/GIF проверяются без перекодирования; оптимизируются PNG, когда копия меньше. Это снижает трафик превью, но не первоначальную загрузку и не общий объём хранения. После аварии может остаться файл производной копии, который повтор использует по детерминированному ID.

WebSocket обеспечивает передачу подключённым клиентам, а не подтверждённое получение каждым офлайн-браузером. При восстановлении интерфейс получает состояние через HTTP.

Outbox требует новой таблицы sm_mq_task, а отображение оптимизированных превью — поля screenshot_optimizations у смены. Эти изменения схемы создаются rebuild; нельзя обещать перенос вообще без изменения схемы БД. Перед production нужны резервная копия, проверка совместимости релиза и план отката. Существующие аккаунты и их данные не нужно пересоздавать.

Для внешней панели нужны действительный сертификат выбранного домена, подтверждённый текущий внешний IP администратора и настройка публикации порта. Пример содержит 158.160.144.108/32. Исходный порт Management оставлять на loopback. Локальные ключи и сертификаты не переносить в production.
